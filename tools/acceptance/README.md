# 验收工具（跑给作者自己看）

这里的东西**只做一件事**：让"不丢稿 / 百万字不卡 / CJK 算得对"这三句话变成**你能自己跑出来的数字**，
而不是我们说了算。脚本只调 `研墨.exe` 自带的验收模式，**不装任何东西**（不需要 Rust、不需要 Python）。

## 怎么跑

0. **需要 0.28.0 或更新的版本**：验收模式是 0.28.0 才进程序的。脚本开跑前会**核对 exe 的文件版本**
   （读文件属性，不运行它；老版本连 `--version` 都不认，运行式检查自己就会挂住）——
   太旧的版本上它会明确停下来说清楚，不会闷头弹个窗口干等。
1. 把这两个 `.bat` 复制到你要测的那台机器上（放哪儿都行）。
2. **双击 `run-acceptance.bat`**：它会自己找 `研墨.exe`（先看同一个文件夹，再看 `%LOCALAPPDATA%\研墨`）。
   - 默认造 1000 章 × 3000 字 ≈ **300 万字**，全程约 1–2 分钟（含开窗那一步）。
   - 想快一点：`run-acceptance.bat --chapters 300`；想更接近"百万字"这个口径：`--chapters 333`。
3. 报告写在脚本旁边：`acceptance-report-<版本>-<日期>.md`（给人看）与 `.json`（给机器看）。
   - 同目录还会有一份 `-ui.log`：界面那一步的**命令级日志**（万一界面没就绪，靠它定位停在哪）。
     里面的标记：`shell.window_building`（开始建窗口）→ `shell.data_ready`（数据层就绪）→
     `window.page_loaded`（页面加载完成）→ 之后是一串前端调用的命令名（`appearance_read`、
     `open_editor_target`…）→ `ui.ready`（界面可用，计时到此为止）。
     停在哪一步，就是哪一步出的问题；一条都没有＝页面根本没加载（多半不是安装版）。

**它不碰你的真实稿库**：验收模式的数据目录在 `%TEMP%\yanmo-acceptance`，脚本开头就把上一次的清掉重建。
位置记录（`yanmo-location.txt`）一个字节都不动。

## 量了什么

| 类别 | 步骤 | 说明 |
| --- | --- | --- |
| 写入 | 造数据·写入 N 章 | 一次性铺完整本书：长篇最真实的那种压力 |
| 读 | 目录树·一次全拉 / 读一章正文 | 打开一本书、打开一章 |
| 改 | 写一章正文 | 改一个字再存回去 |
| 检索 | 检索·四字 / 两字 / 一字 | 四种查询形态（三个字以上走全文索引，更短的回退全扫） |
| 耐久 | 库体检 quick_check / **一致性快照·备份一次** | 大库备份要多久，也是"不丢稿"的关键数字 |
| 启动 | 关库再打开 / **界面冷启动到可输入** | 后者由**另一个进程**量：先开窗，再记到界面可用的时间 |

**界面冷启动为什么单独开一个进程**：同一个进程里先跑完数据基准，程序文件早就进了系统缓存，
量出来的"冷启动"会偏乐观。分开跑才是真的冷启动。

## 两台机器怎么比

同一份脚本、同一个版本，在两台机器上各跑一遍，把两份 `.md` 并排贴：

- 数字**随机器变**是正常的（CPU / 内存 / 磁盘都不一样），所以我们把机器的型号与内存写进报告——
  没有这一栏的数字没法比。
- 拿一台**低配机**当基准：低配机跑得动，才叫"百万字不卡"。

## 启动体检（`diagnose-ime.bat`）

只在**"打开后打不出中文"这类只在个别机器上出现的毛病**时才用：它把这条链记成时间线——
进程启动 → 页面加载 → 窗口有没有拿到焦点 → **焦点元素是谁（每秒一次，看头 6 秒）** →
正文焦点进出 → **输入法组字事件有没有来** → 每个按键/点击（含 IME 的 229）。

日志写在脚本旁（GUI 程序在控制台里没有可用的标准输出，所以一律落文件）。
如果这台机器装了不止一个 WebView2 运行时，它还会**用较旧的那个再跑一遍**，用来分清"是运行时的锅"还是"我们的锅"。

实测价值：研墨自己那个"启动打不出中文"的毛病就是靠这份日志定案的——窗口有焦点、正文也拿到了焦点，
但**组字事件一个都不来**，于是定位到"输入法没挂到正文上"，而不是焦点问题。

## 不丢稿演练（`drill-safekeeping.bat`）

是一个"真的把 App 杀掉再看稿子在不在"的演练，全程在 `%TEMP%\yanmo-drill` 沙盒里：

1. 沙盒里放一份**便携版**副本（数据就在沙盒里，绿色版不会去认领你机器上的稿库）；
2. 铺 50 章，打印一次账（章数 / 字数）；
3. 打开它，请你在窗口里随便写几个字；
4. **硬杀**（等价于断电、崩溃、任务管理器结束进程），只有沙盒这一份被杀；
5. 再打开，再打印一次账：**章数与字数只该往上走，绝不该少**。

想更狠一点：拔电源、或在第 3 步写到一半时直接杀——两种都试过也应该一样。

## 已知边界（这些不是 bug，是如实告诉你）

- **不建议把稿子放同步盘或移动盘**：OneDrive 之类会来回上传、偶尔回滚文件，SQLite 撞上会坏库；
  U 盘/移动盘写到一半被拔同理。软件在选位置时会提示，但不拦你（那是你的机器）。
- **同一个数据目录同时只允许开一个研墨**：第二个实例会被拦住并提示（两个进程写一个库是真会坏的）。
- **中文输入法**：Windows 输入法在 WebView2 的正文区有上游未修缺陷（首字丢失、全角标点要按两次），
  页面里的普通输入框不受影响。我们能控的激活/焦点时序已经处理过。
